# План розгортання

## Загальна схема

Зберігаємо frontend, backend, документацію та історію комітів в одному GitHub-репозиторії. У хмарі frontend і backend працюватимуть як окремі сервіси.

```text
GitHub (один репозиторій)
    ├── frontend/  → Vercel (React + Vite)
    └── backend/   → Render (Node.js + Express)
                           │
                           └── PostgreSQL (окремий сервіс)
```

Це **план**, а не опис уже працюючого деплою. Реальні URL, команди збірки й інструкції додамо після ініціалізації застосунків.

## Vercel — frontend

- Під'єднати наш GitHub-репозиторій як окремий Vercel Project.
- Вказати **Root Directory:** `frontend`.
- Вибрати збірку Vite (вихідна папка — `dist`, якщо не змінимо стандартні налаштування).
- Налаштувати `VITE_API_URL` на публічну HTTPS-адресу backend. Це публічна змінна, **не секрет**.
- Якщо використовуватимемо React Router і прямі переходи на внутрішні сторінки, додати SPA rewrite на `index.html`.

## Render — backend

- Під'єднати той самий GitHub-репозиторій як **Web Service**.
- Вказати **Root Directory:** `backend`.
- Після створення npm-скриптів налаштувати інсталяцію, збірку TypeScript і запуск зібраного серверного коду.
- Слухати порт із `PORT`, заданого середовищем Render; не прив'язувати сервер до `localhost`.
- Задати серверні змінні `DATABASE_URL`, секрет автентифікації та дозволений frontend origin (назви змінних уточнимо під час реалізації).
- Дозволити CORS лише для потрібних origin, а не для всіх сайтів. Продумати preflight-запити та передачу облікових даних відповідно до обраного способу авторизації.
- Міграції продакшн-БД запускати контрольовано через `prisma migrate deploy`; не використовувати команди скидання БД.

## PostgreSQL

Локально запускаємо PostgreSQL через Docker Compose. Для хмари обираємо окремий керований PostgreSQL, який можна під'єднати до Render. Не розміщуємо БД у файловій системі контейнера backend.

**Звернути увагу:** безкоштовна база Render Postgres за поточними правилами має строк життя 30 днів. Якщо демонстрація або захист будуть пізніше, краще вибрати довговічніше сховище або мати продуманий спосіб відновлення тестових даних. У безкоштовного Render Web Service також може бути затримка після простою.

## Перед фінальним захистом

- Перевірити локальний запуск за README.
- Перевірити публічну доступність frontend і backend та підключення до БД.
- Перевірити CORS, авторизацію й обмеження доступу за ролями.
- Виконати міграції та заповнити БД тестовими даними для демонстрації.
- Пройти сценарії видачі, повернення, втрати книги та формування звітів.
- Додати справжні посилання на сервіси та точні інструкції в README.
